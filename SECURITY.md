# Security Policy

`bitmask` is often used in security-sensitive contexts, such as Role-Based Access Control (RBAC), permission management, and authorization middleware. We take security vulnerabilities very seriously.

---

## Supported Versions

Only the latest release of `bitmask` receives security patches.

| Version | Supported          |
| ------- | ------------------ |
| v1.x    | :white_check_mark: |
| < v1.0  | :x:                |

---

## Reporting a Vulnerability

If you discover a security vulnerability in `bitmask`, please follow responsible disclosure practices:

1. **Do NOT open a public GitHub issue.**
2. Send an email to the maintainers or report via GitHub Private Vulnerability Reporting if enabled.
3. Include:
   - A detailed description of the vulnerability.
   - Steps or a minimal reproducible code snippet to demonstrate the issue.
   - Potential impact on access control or permission checks.

### What to Expect
- **Acknowledgement:** We will acknowledge receipt of your vulnerability report within 48 hours.
- **Assessment:** We will confirm the vulnerability and assess its severity.
- **Fix & Disclosure:** We will work on a fix in a private branch, tag a new release, and coordinate public disclosure.

Thank you for keeping `bitmask` and its users safe!
